# myvideo 平台需求文档（v0.1 · 专家评估稿）

> 目的：征求各位对产品定位、技术路线、开源与商业模式的整体评估。
> 文中"已验证"= 已有端到端生产实践支撑；"规划"= 设计意图，尚未实现。
> 欢迎直接在第 11 节的问题上拍砖。

---

## 1. 一句话定位

**把 AI 短片生产的全工序（文稿→分镜→图像→视频→质检→配音→字幕→混音→成片）
产品化为一条带质量闸门、本地优先、云端可插拔的流水线**，让一张消费级显卡的
个人创作者也能稳定产出达到发布标准的成片。

## 2. 背景

- 现有"一键出片"工具（开源与商业）解决的是**能出片**，普遍存在镜头一致性差、
  音画错位、响度/字幕不合平台规范等问题，产出往往"能看不能发"。
- ComfyUI 生态能 reach 到发布质量，但节点工作流的学习与运维成本把内容创作者挡在门外。
- 我们已用自研脚本+固定工序在单卡 RTX 4090 上端到端产出过多条达到
  发布标准（响度/对齐/画幅合规、逐镜通过 vision 评审）的竖屏成片，本文把这些
  经验产品化。

## 3. 目标与非目标

**目标**
1. 本地优先：不注册任何云服务、不上传任何素材，凭本机 4090 + 本地模型可完成整片。
2. 质量闸门内置：不合格产物不流转（评审不过不进下一步），失败可定位到单镜。
3. 云端可插拔：每个环节可独立切换本地/云端供应商，无厂商锁定。
4. 多集一致：同一套契约支撑连续剧集生产。

**非目标**
1. 不做通用 ComfyUI 前端（不与 node 编辑器竞争，节点图是实现细节不是用户界面）。
2. 不自建 GPU 算力集群（重资产，不碰）。
3. 不做在线剪辑器（时间轴精剪交给专业工具，本平台负责"生成+组装+合规"）。

## 4. 目标用户

| 画像 | 特征 | 付费点 |
|---|---|---|
| 有卡的个人创作者 | 4090/5090，会用 pip/ssh，不想学 ComfyUI | 云能力升级（本地搞不定的那一下）、模板 |
| 无卡的内容团队 | 有选题与分发，无 GPU/运维 | 托管出片、按成片量计费 |
| 开发者 | 想二次开发或接入自有模型 | 开源核心 + API |

官方支持档：**Windows + RTX 40xx + ComfyUI**（我们有实测数据的环境）；
其余配置尽力而为、社区互助。

## 5. 核心用户场景

- S1「选题到成片」：输入一段主题描述或自备文稿 → 生成分镜草案 → 人工确认 →
  自动跑关键帧（每镜 3 候选拼宫格）→ vision 评审+人工圈选 → 图生视频 →
  质检（不过自动重做 ≤2 次）→ 配音/字幕/BGM → 总装交付，全程断点可续。
- S2「单镜急救」：某镜始终不合格 → 单独把这一镜升级到云端视频模型重做，
  其余保持本地，成本透明到镜。
- S3「剧集排产」：project.json 定义风格契约/角色资产/规格 → 按集批量排产，
  状态机推进，人工只在锁稿/选优/终审三处介入。
- S4「开发者接入」：clone → 填 config → 用 core/post 脚本搭自己的流水线，
  或只取质量闸门模块嵌入现有系统。

## 7. 非功能需求

- **幂等与断点续跑**：同任务重复提交跳过已完成产物；任何一步崩溃后从 state.json 恢复。
- **可审计**：每个产物记录 prompt/seed/模型/评分/时间，成片可逐镜溯源。
- **隐私**：本地模式零外发；云端模式明示每一处外发内容与目的。
- **密钥卫生**：API key 只走环境变量/本地加密存储，不落仓库、不进日志。
- **确定性**：TTS 同文本重录同结果；图像/视频以 seed 记录复现。

## 8. 架构概览（四层）

```
┌─ UI 层      Web 向导 + 看板 + 圈选/试听/红绿灯（规划中）
├─ 领域层     质量闸门(评分细则/对齐/响度) · 素材与契约库 · ffmpeg 配方 · 状态机
├─ 编排层     FastAPI + SQLite：任务 DAG、路由决策、断点续跑、计量
└─ GPU/供给层 ComfyUI(本地图/视频/TTS) · Ollama/vLLM · 云 API（多供应商）
```

关键原则：**闸门即数据**——评审标准、对齐规则、响度口径都是可配置的数据
（YAML/JSON），不是硬编码；这使模板库与社区贡献成为可能。

## 9. 开源策略（open-core）

| 层 | 开源（MIT，即本仓库） | 托管闭源 |
|---|---|---|
| 工序脚本与闸门 | ✅ 全量 | — |
| schema/模板 | ✅ 基础模板 | 精品模板库 |
| 编排引擎 | ✅ 单机版 | 多租户/计费版 |
| 托管能力 | 必须可完全不用（本地可用是信任底线） | 云端生成、积分计费 |

说明：BYOK（用户自带任意 API key）不设拦截——开发者的逃逸口就是开源的可信度；
托管侧靠"开箱顺滑 + 首发额度"竞争，不靠锁。

## 10. 商业模式（诚实版）

- **飞轮**：开源工具获客 → 用户自然遇到本地能力上限（小模型文稿质量、
  无卡、单镜急救）→ 引导到官方 API（LLM/VLM/图像/视频 token）按量变现。
  API 转售已在运营（https://enk.llc/ ，含 LLM 与视频生成 API），
  缺的是与平台打通的自助计费与积分抽象（FR-12）。
- **变现锚点排序**：①单镜升云微交易（付费意愿最高的一下）②无卡用户整片托管
  ③精品模板/资产订阅 ④团队版多租户。
- **已识别风险**：a) 视频 API 转售的上游授权与价格波动；b) 开源核心足够好后
  用户永久停留免费层；c) 质量闸门对云端模型的评分适配成本；d) 消费级硬件
  性能预期管理。均欢迎给意见。

## 11. 请专家重点评估的开放问题

1. 质量闸门用 vision 模型自动评分（阈值 8/10 放行）——不同 VLM 间分数不可比，
   校准与换模迁移怎么做才工程可靠？
2. "本地优先"与"云变现"的边界：把最好的模型效果留给云端是否会让开源版
   口碑反噬？免费档体验做到什么程度是平衡点？
3. 按环节计量（token/张/秒/字符）→"成片额度"的抽象，会不会因成本结构
   （模型降价、重跑率）击穿定价？定价模型怎么设计留有余地？
4. 单卡 24GB 串行排队是硬约束，多卡/分布式值得做吗，还是引导用户升云？
5. 与现有开源项目（如各类 MoneyPrinter 系工具）的差异化叙事是否成立？
   会不会陷入同质化？
6. 多供应商视频路由（接口协议、产物规格、失败降级）的最佳实践？
7. 一键 worker 的模型分发合规：只发"下载清单+校验和"是否足够安全？
8. 剧集状态机是否应支持并行人工审批（多人协作）？投入产出比如何？
9. 对这个量级的团队，P0→P3 的里程碑切分有没有明显的坑？

## 12. 里程碑

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| P0（现在） | 本仓库：核心工序库+闸门+schema+文档 | 会命令行的人能端到端出片 ✅ 部分达成 |
| P1 | 编排引擎（DAG/断点/路由）+ Web UI 最小版 + 一键 worker | 目标用户不读代码完成 S1 |
| P2 | 计费打通（自助 key/积分）+ 云端视频路由 + 精品模板 | 无卡用户可付费出片 |
| P3 | 剧集排产 UI + 模板市场 + 社区资产共享 | 月活产出稳定增长 |

## 附录 A · 性能参考（RTX 4090 24GB，实测口径）

- 关键帧 t2i（1536×2688，20 steps，fp8 量化 20B 级模型）：约 20~60 s/张
- 图生视频（768×1344，124 帧 ≈5.2 s）：约 90~105 s/条
- TTS（本地部署，数十秒音频）：约 5~10 s/句
- 全片（约 75 s / 12 镜 / 每镜 3 候选）GPU 时间：约 40~60 分钟（含质检重跑）

以上为单一硬件+特定模型档位的实测值，不构成跨条件可比承诺；不同模型/量化
档位会有数倍差异。
